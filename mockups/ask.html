Explain the xz / CVE-2024-3094 backdoor — how did it actually get a foothold?
R
RIFTRecon · ASK

CVE-2024-3094 was a supply-chain backdoor planted in the xz-utils compression library (versions 5.6.0 and 5.6.1). The short version:

A long-trusted maintainer introduced obfuscated payloads hidden inside test fixture files — binary blobs that looked like corrupt test data. During the build, a modified build-to-host.m4 script extracted and injected them, so the malicious code never appeared in the public git source — only in the release tarballs.

liblzma → sshd hook (via systemd link)
# simplified flow sshd → libsystemd → liblzma (xz) liblzma hooks RSA_public_decrypt via IFUNC resolver → attacker key bypasses auth, runs commands as root

The payload hooked the SSH daemon’s RSA verification through an IFUNC resolver, letting an attacker with the right key skip authentication entirely. It was caught early — a Microsoft engineer noticed sshd using ~500ms more CPU than expected.
